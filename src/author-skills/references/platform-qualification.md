# Platform Qualification

Interactive Missions supports the following workspace-launch adapters:

| Client | Adapter ID | Workspace surface |
| --- | --- | --- |
| OpenAI Codex | `codex` | `.codex/skills/mission-tutoring` and `AGENTS.md` |
| Claude Code | `claude-code` | `CLAUDE.md` and `mission-tutoring.md` |
| Gemini CLI | `gemini-cli` | `GEMINI.md` |
| GitHub Copilot in VS Code | `github-copilot-vscode` | `.github/copilot-instructions.md` and prompt |
| GitHub Copilot CLI | `github-copilot-cli` | `COPILOT.md` |
| Generic client | `generic` | `AGENTS.md` and `START_MISSION.md` |

The launch prompt generated by `prepareWorkspace` is authoritative. Codex uses `$mission-tutoring`; Claude Code uses `/mission-tutoring`; Gemini uses `GEMINI.md`; Copilot in VS Code uses the generated prompt file or prompt command; Copilot CLI uses `COPILOT.md`; and Generic clients use `START_MISSION.md`.

Each adapter must prepare the learner workspace, identify the copied
`mission-tutoring` skill, preserve the workspace-local progress contract, and
fail clearly when required MATLAB&reg; MCP capabilities are unavailable.

`startMissionAuthoring()` uses the same supported client IDs to copy the matching authoring adapter. The selected adapter points the client to the portable `create-tutor-mission`, `qa-mission`, and `maintain-missions` skills in the new workspace.

## Feedback And Logging

Interactive Missions does not provide an in-product feedback route or session
logging surface. Do not route learners to an unowned public channel, collect
session data, or promise support handling until the owning policy is defined.

The machine-readable support source is
[`agent-support-matrix.json`](agent-support-matrix.json). Keep it aligned with
the marketplace manifest, app client selector, adapters, and smoke tests.
